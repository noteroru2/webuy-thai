# แผนการดำเนินงานกู้คืนระบบ SEO (SEO Recovery Implementation Plan)

**โครงการ:** เรารับซื้อ.com V2 Recovery  
**ระยะเวลาคาดการณ์:** 4-6 สัปดาห์ (แบ่งการทำงานเป็น 6 รอบการทำงานย่อย)

---

## 1. จุดแก้ไขเร่งด่วนที่สุด (Quick Wins) ที่ได้ประโยชน์สูงสุด
1. **คัดแยกหน้าเพจสแปมและส่งรหัส HTTP 410 (Gone):** ลบหน้าเพจ "รับซื้อเหล้า", "ตั๋วจำนำ", "รับซื้อกระดาษ" และตั้งค่าระบบส่งรหัส 410 ในระบบเซิร์ฟเวอร์ย่อย เพื่อกวาดล้างหน้าขยะออกจากการคราวด์ของ Google อย่างรวดเร็ว ป้องกันการตกหล่นของ Domain Authority
2. **ลบเนื้อหาล่อบอท (AEO/GEO Meta Text) ที่มองเห็น:** ปรับปรุงไฟล์ `src/components/home/SeoProseSection.astro` โดยลบหัวข้อ *"คำแนะนำสำหรับ Answer Engine (AEO)"* และ *"Generative AI Summary (GEO)"* ออกทันที เพื่อลดโอกาสโดนระบบตรวจจับ Helpful Content ลดคะแนนความน่าเชื่อถือ
3. **ทำระบบสกัดคำสะกดผิด / หางขาด:** ย้ายหน้าท้องถิ่นสะกดผิด (เช่น `ศรีสะเก`, `กาฬสินธ`) ไปทำ 301 Redirect เข้าหาหน้าหลัก ปรับโครงสร้างภายในไม่ให้ลิงก์ไปหา URL ที่บกพร่องเหล่านั้นอีก
4. **เปิดการใช้งานสคริปต์กรอง sitemap แบบเข้มงวด:** ปรับสคริปต์ `generate-sitemaps.mjs` ให้ไม่ดึงหน้าที่มีปัญหาหรือหน้าจังหวัด Mass Programmatic ที่ตกลงทำ NOINDEX เข้าไปในไฟล์ xml เพื่อทำให้ดัชนีส่งตรวจสะอาด 100%

---

## 2. ความเสี่ยงที่ควรระวังก่อนเริ่มดำเนินการ (Risk Analysis)
* **ความเสี่ยงด้านอันดับคีย์เวิร์ดแกว่งชั่วคราว (Ranking Volatility):** การลบไฟล์บทความท้องถิ่นจำนวนหลายร้อยไฟล์และการส่งรหัส 410/301 พร้อมกันเป็นจำนวนมาก อาจทำให้ Googlebot เข้ามา Crawl ถี่ขึ้นในช่วงแรก และทำให้อันดับของเว็บโดยรวมมีการปรับเปลี่ยน (Dance) ชั่วคราว 2-3 สัปดาห์ ก่อนจะนิ่งและดีขึ้น
* **งบประมาณคราวด์ถูกใช้จนล้น (Crawl Budget Spike):** เมื่อกูเกิลพยายามอัปเดตหน้าเว็บที่ปิดตัวลง ระบบหลังบ้านจะถูกเรียกอ่านรหัส 410 เป็นจำนวนมาก ต้องเตรียมความพร้อมด้านประสิทธิภาพเซิร์ฟเวอร์โฮสติ้ง (เช่น Cloudflare หรือระบบหลังบ้าน) ไม่ให้ล่มขณะเกิดการ Crawl รอบใหญ่
* **การส่ง Canonical ผิดพลาดชั่วคราว:** การทำ Canonical ชี้จากหน้าย่อยระดับเขตเข้าสู่หน้าศูนย์กลาง ต้องตรวจดูไม่ให้เกิดลูปการสลับ Canonical ไปมาจนบ็อทสับสน

## 3. แผนการดำเนินงานเป็นกลุ่ม (Batch Roadmap)

### Batch 1: Cleanup Indexability + Sitemap (ทำความสะอาดดัชนีและการส่งแผนผังเว็บไซต์)
* **เป้าหมาย:** สกัดกั้นคอนเทนต์ที่มีคุณภาพต่ำและไม่เกี่ยวข้องออกจากสารบบของกูเกิล
* **ขั้นตอนการทำงาน:**
  1. ลบไฟล์บทความรับซื้อเหล้า จำนำ และคอนเทนต์นอกเรื่อง (Off-Topic) ในโฟลเดอร์ `src/content/posts/` ทั้งหมด
  2. แก้ไขไฟล์ `src/pages/[slug].astro` และระบบ Middleware ให้รับรู้รายการไฟล์ที่ถูกลบไปแล้ว และส่งรหัส HTTP Status 410 Gone แทนที่จะปล่อยเป็น 404
  3. ปรับฟิลด์ข้อมูลใน Markdown ท้องถิ่นระดับอำเภอย่อย (Thin Content) ให้มีค่า `noindex: true`
  4. อัปเดตและทดสอบสคริปต์ `scripts/generate-sitemaps.mjs` เพื่อให้กรองลิงก์ที่ไม่เกี่ยวข้องออกทั้งหมดหลังจากการ Build เสร็จสิ้น

### Batch 2: Rewrite Core Pages (ปรับปรุงเนื้อหาหน้าแกนหลัก)
* **เป้าหมาย:** เขียนเนื้อหาของหน้าเพจทำเงินหลัก (Money Pages) เพื่อเพิ่มคะแนนความน่าเชื่อถือตามหลักเกณฑ์ E-E-A-T ของกูเกิล
* **ขั้นตอนการทำงาน:**
  1. นำข้อมูล claim-heavy เช่น "สู้ทุกราคา" หรือ "ราคาสูงที่สุดในประเทศ" ออกจากไฟล์หลัก เช่น `รับซื้อโน๊ตบุ๊ค.astro` และ `รับซื้อคอม.astro`
  2. แปลงเนื้อหาให้เน้นการประเมินราคาอย่างโปร่งใส ระบุแนวทางการตรวจรับเครื่อง ขั้นตอนความปลอดภัยของข้อมูลลูกค้า (Data Sanitation) แทนการขายฝันเรื่องราคา
  3. แก้ไขข้อความใน `SeoProseSection.astro` บนหน้าแรก ให้บริการเนื้อหาแบบธรรมชาติ (Natural Reading) เป็นประโยชน์ต่อคนอ่านจริงๆ

### Batch 3: Internal Link + Navigation Cleanup (ปรับโครงสร้างลิงก์ภายในและเมนู)
* **เป้าหมาย:** ล้างโครงสร้างลิงก์ที่ไม่เกี่ยวข้องที่เชื่อมไปยังหน้าออฟทอปิกออกทั้งหมด
* **ขั้นตอนการทำงาน:**
  1. เขียนสคริปต์หรือใช้ระบบแทนที่ข้อความ ลบโครงสร้างการลิงก์ข้างขอบทาง (Sidebar/Footer links) ที่แนะนำลิงก์สแปม (เช่น ลิงก์จำนำ หรือลิงก์รับซื้อเหล้า)
  2. จัดสรรผังลิงก์จากหน้าย่อยท้องถิ่น เช่น จังหวัด ให้ชี้กลับมาสนับสนุนหน้าหลัก Hub เสมอด้วย Anchor Text ที่เป็นธรรมชาติ
  3. ปรับเมนูนำทางหลักของเว็บไซต์ (Main Navigation) ใน `LandingNav.astro` ให้มีโครงสร้างเรียบง่ายและเป็นลำดับขั้นตอนชัดเจน

### Batch 4: Structured Data (Schema) + Trust/Entity (ปรับปรุงข้อมูลโครงสร้างและเอนทิตี)
* **เป้าหมาย:** ปรับลด Schema ที่ซ้ำซ้อนกันเพื่อสร้างความชัดเจนให้กับบอทของ Search Engine
* **ขั้นตอนการทำงาน:**
  1. ตรวจสอบและลดทอน Schema ใน `รับซื้อโน๊ตบุ๊ค.astro` และเพจอื่นๆ ให้เหลือเฉพาะสกีม่าหลักที่จำเป็น เช่น เก็บ `Service` และ `FAQPage` ไว้ ยุบรวมสกีม่าอื่นๆ
  2. ปรับแต่งไฟล์ `src/layouts/BaseLayout.astro` ให้ตรวจสอบสิทธิ์ของเพจก่อนแสดงผล `LocalBusiness` หรือย้าย Schema ไปทำงานบนหน้าหลักกับหน้าติดต่อเราเท่านั้น
  3. ตรวจสอบความถูกต้องของสกีม่าขนมปัง (BreadcrumbList) เพื่อให้สอดคล้องกับพิกัดที่แท้จริง

### Batch 5: Mobile UX Polish (ขัดเกลาประสบการณ์บนโทรศัพท์มือถือ)
* **เป้าหมาย:** ปรับโครงสร้างหน้าเพื่อยกระดับผลคะแนน Core Web Vitals และความสะดวกในการใช้งานบนอุปกรณ์พกพา
* **ขั้นตอนการทำงาน:**
  1. ปรับปรุง H1 ของทุกหน้าหลักให้กระชับ ยาวไม่เกิน 40 ตัวอักษร เพื่อไม่ให้ตกบรรทัดเยอะจนดันเนื้อหาและส่วน CTA ลงไปด้านล่าง
  2. แก้ไข component `ProvincialGrid.astro` โดยใช้ระบบ Lazy loading, สร้างปุ่ม "ดูจังหวัดทั้งหมด" หรือแบ่งหมวดหมู่ภูมิภาคเพื่อไม่ให้โหลดลิงก์ 70+ ลิงก์พร้อมกันบนมือถือ
  3. ตรวจสอบระยะเวลาการตอบสนองและเฟรมเรตการทำงานของสไลเดอร์ธุรกรรมล่าสุดบนมือถือ

### Batch 6: QA + Build + GSC Resubmission (ตรวจสอบคุณภาพและส่งขอจัดทำดัชนีใหม่)
* **เป้าหมาย:** นำระบบผ่านการตรวจสอบทางเทคนิคและส่งดัชนีเพื่อกู้คืนทราฟฟิกกลับมา
* **ขั้นตอนการทำงาน:**
  1. รันระบบคอมไพล์ `npm run build` เพื่อให้แน่ใจว่าซอร์สโค้ดและ Integration ทำงานได้โดยไม่มีข้อผิดพลาด
  2. รันคำสั่งตรวจสอบ SEO `npm run seo:audit` อีกครั้งเพื่อยืนยันว่าจุดผิดพลาด (Errors/Warnings) ลดลงจนอยู่ในเกณฑ์มาตรฐานความสะอาดสูงสุด
  3. ส่งไฟล์ `sitemap-index.xml` ตัวใหม่ขึ้นระบบ Google Search Console
  4. ทำเรื่องแจ้งขอตรวจสอบแก้ไขปัญหาการคราวด์ (Validate Fix) ในหมวดหมู่ต่างๆ ของ GSC
